# Noveo iOS port

First stage: a Foundation-only Noveo transport module, with Bazel integration and an isolated Swift package for protocol checks. It implements Noveo's first-frame WebSocket password login/resume, session parsing, account-generation isolation, authentication timeout, incoming frame stream and topic-aware message envelopes. Document IDs preserve full 64-bit precision; plans use 50/100/500 MiB limits. No credentials are logged or persisted in preferences.

This module is not wired into Telegram's account/login UI yet. Existing Telegram UI, account storage, Postbox histories, media, calls and APNs are still Telegram-backed. Do not distribute this fork as a working Noveo app yet.

Second stage: device-only Keychain storage keyed by local AccountRecordId, a per-account authentication coordinator with password/TOTP/resume/cancellation/logout states, and TelegramEngineUnauthorized.Auth.makeNoveoAuthenticationCoordinator(). The password exists only in the outgoing login frame; only the issued session token is persisted. Transport failures retain stored sessions; late cancelled completions cannot write credentials. Login challenges follow the backend's login_totp_required / login_totp_verify / login_totp_error frames. Native account authorization has not been fabricated: it must be committed with a valid local Noveo user and history adapter.

Next: username/password/code-entry UI, Noveo UUID/native peer and message ID mapping, and Postbox/TelegramEngine ingestion of users/dialogs/history/live messages. Then adapt upload/download, forum routing, notifications/APNs, membership/stars/gifts and account sync. Retain native Telegram cache and topic isolation rather than emulating all chats as one history.

The repository pins Xcode 27.1 / macOS 27 in versions.json. GitHub now provides this toolchain on its xcode-27 hosted runner; the manual Noveo full simulator build workflow uses it, builds the complete target, and retains a bounded Bazel disk cache even after build failure. Relative rlottie/tgcalls submodule URLs now explicitly resolve to their upstream organization, rather than nonexistent sibling repos under a fork owner. This Linux workspace cannot compile/run the complete UIKit app or record simulator frame verification required by AGENTS.md. The separate Noveo transport workflow compiles/tests only the Foundation module on a macOS host; it does not prove an app build. Existing app build cache/configuration is retained. The legacy macos-13 release workflow is not used for Noveo simulator validation. A real-device install/release still needs Noveo bundle identifiers, signing profiles and Apple push configuration. The inherited release workflow remains manual-only; simulator checks do not publish releases. Transport checks run automatically and retain their cache; no full-app cache was removed.

The peer identity foundation maps UUIDs to collision-free local integer IDs, validates account ownership on restore, and preserves mappings in serialized snapshots. The future Postbox adapter must save each snapshot atomically with peer writes. Groups/channels retain one chat identity across type changes; DMs use the counterpart user identity. This is not a message-ID allocator: history ordering/cursors require a separate adapter before ingestion can be enabled.
